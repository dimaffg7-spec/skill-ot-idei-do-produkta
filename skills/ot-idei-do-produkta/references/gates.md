# Паспорт среды и гейты

Гейт - это команда, которая либо проходит, либо нет. Не мнение агента о своей работе.

## Паспорт среды снимается один раз, в самом начале

Пока не известно, чем проект проверяется, любое «я всё проверил» - слова. Паспорт
записывается в `architecture/00-passport.md` и дальше служит единственным источником команд:
агент не сочиняет команду из головы, он берёт её отсюда.

Что выясняется:

| Строка паспорта | Как выясняется |
|---|---|
| менеджер пакетов | есть `pnpm-lock.yaml` → pnpm; `package-lock.json` → npm; `yarn.lock` → yarn |
| команда сборки | раздел `scripts` в `package.json` |
| линт | там же |
| тесты | там же; нет раздела - записываем «тестов нет» |
| как запускается | `dev` / `start` из `scripts` |

По умолчанию - **pnpm**, не npm.

## Базовая линия

Сразу после паспорта команды прогоняются один раз, до единой правки, и результат
записывается: сколько проверок падает **сейчас**. Дальше регрессией считается только рост
этого числа. Иначе чужой проект, который не собирался изначально, будет вечно выглядеть
как «мы всё сломали».

## Гейты перед закрытием фазы

Прогоняются все, что есть в паспорте. Фаза не закрывается, пока не пройдены.

Нет ни одной автоматической проверки - **режим меняется**: объём фазы режется вдвое, каждая
фаза заканчивается показом человеку, автономная работа выключается. Это не наказание,
а честность: проверять нечем, значит проверяет человек.

## Жёсткие правила, которые не отключаются

Эти пять держатся на всех шагах, независимо от режима и размера задачи.

1. **`git add` поимённо.** Никогда `git add .` и `git add -A`: рядом могут лежать чужие
   незаконченные правки.
2. **Не выкатывать без прямой команды.** Push в основную ветку и деплой - только когда
   человек сказал это словами. Подготовку доводим до конца, кнопку не жмём.
3. **Секреты не читать.** Реальный `.env` не открывается никогда. Нужен список переменных -
   берётся `.env.example`.
4. **Перед push - сборка, а не только типы.** Сборка ловит то, что проверка типов пропускает.
   Линт гоняется отдельной командой: сборка линтует не весь проект.
5. **Удаление - только с подтверждением** и только после показа, что именно будет удалено.

## Опасная тройка

Персональные данные людей · чужой контент · отправка чего-либо наружу. Есть хотя бы одно -
работа доводится до готовности, но последний шаг делает человек. Отправляющая часть
рождается выключенной.
