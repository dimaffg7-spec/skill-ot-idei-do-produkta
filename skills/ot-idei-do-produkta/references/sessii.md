# Сессии, контекст и передача

Полный маршрут - 14 шагов идеи, 11 шагов архитектуры и код - в одно окно не помещается.
Это не недостаток, это физика: качество ответов падает по мере заполнения контекста.

## Правило 40%

Контекст заполнен больше чем на 40% - агент глупеет: начинает терять сказанное в начале
и повторяться. Поэтому:

- работаем в первых 40-60% окна;
- заполнилось - **сначала пишем передачу, потом чистим контекст**, не наоборот;
- после чистки новая сессия начинается с чтения файла передачи, а не с пересказа по памяти.

## Границы сессий по умолчанию

| Сессия | Что закрывает |
|---|---|
| 1 | Дом проекта и бизнес-контекст: шаги 3.1-3.2 |
| 2 | Идея: шаги 3.3-3.14, папка `idea/` |
| 3 | Архитектура, первая половина: шаги 5.0-5.5 |
| 4 | Архитектура, вторая половина: шаги 5.6-5.10 + приёмка архитектуры |
| 5+ | Код: одна фаза плана = одна сессия |

Это разметка по умолчанию. Проект маленький - сессии склеиваются, большой - режутся мельче.

## Передача

Файл `plans/<задача>/peredacha.md`, переписывается перед каждой чисткой контекста.
Формат - в `templates/peredacha.md`. Правило одно: **шаг, который не оставил файла,
не случился.** Прогон обязан пережить закрытое окно, а не жить в памяти сессии.

## Чек-лист прогона

`plans/<задача>/checklist.md` - плоский список всех шагов маршрута со статусами:

- `[ ]` не начат
- `[WIP]` в работе
- `[x]` закрыт, и под ним есть файл
- `[!]` заблокирован, нужен человек

Отметка `[x]` без файла на диске закрытием не считается. Это единственная защита от
«агент сказал готово».
